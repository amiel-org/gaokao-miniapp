# 高考志愿填报小程序

## 1. 项目定位

这是一个面向更广泛高考考生和家长的微信小程序，不只服务“色弱受限”这一类特殊情况，而是围绕志愿填报中的核心决策问题，提供：

- 基于分数/位次的院校与专业筛选
- 基于选科要求的可报专业过滤
- 基于身体条件或特殊限制的风险提醒
- 基于冲稳保策略的志愿建议

当前仓库里已有的北京高考数据、学校目录、专业限制、分数映射和报告脚本，可以直接作为这个小程序第一阶段的数据基础。

## 2. 第一版不要做太大

第一版只做 MVP，目标不是“一步做到全国最强”，而是先做出一个真正能用的北京版志愿辅助工具。

推荐第一版范围：

- 地区先只做北京
- 批次先只做本科普通批
- 用户输入分数或位次
- 用户选择选科组合
- 用户可勾选特殊情况
- 系统输出“可报院校/专业”与“冲稳保建议”

先不做的内容：

- 全国多省份统一适配
- 完整模拟填报流程
- AI 问答型助手
- 登录、支付、分享裂变
- 复杂的专家系统规则引擎

## 3. 目标用户

核心用户不是单一特殊群体，而是三类：

- 普通考生和家长：想知道这个分数大概能报什么
- 有限制条件的考生：例如色弱、色盲、身高、体检要求等
- 想快速做志愿初筛的人：先形成一批可报学校和专业，再细化选择

## 4. 第一版核心功能

### 4.1 信息录入

用户进入后先填写：

- 所在地区：北京
- 成绩类型：分数 / 位次
- 高考分数
- 对应位次
- 选科组合
- 倾向城市
- 倾向院校层次
- 特殊条件标签

特殊条件标签第一版建议这样做：

- 无特殊限制
- 色弱/色盲
- 医学类谨慎
- 化学实验类谨慎

这里不要一开始做得太细，先做成“风险标签”，后面再扩展。

### 4.2 院校与专业推荐

根据输入条件，输出：

- 可报院校列表
- 可报专业列表
- 每个专业对应的选科要求
- 近年参考分数/位次
- 风险提示

推荐结果按三档展示：

- 冲刺
- 稳妥
- 保底

### 4.3 专业限制提醒

这是你当前仓库最有价值的差异化能力之一。

除了常规志愿筛选，系统要对用户标注：

- 明确受限
- 建议谨慎
- 当前未见明确限制

这部分可以直接复用已有的规则和脚本思路。

### 4.4 志愿单保存

第一版建议支持：

- 收藏院校/专业
- 生成“我的备选单”
- 按冲稳保分组查看

先不必上来就做复杂排序和批量导出。

## 5. 建议的小程序页面结构

第一版页面建议控制在 5 个以内：

1. 首页
   - 产品介绍
   - 开始填报按钮

2. 条件填写页
   - 分数/位次
   - 选科
   - 偏好
   - 特殊限制

3. 推荐结果页
   - 冲稳保 Tab
   - 学校卡片
   - 专业卡片

4. 学校/专业详情页
   - 学校信息
   - 专业要求
   - 风险说明
   - 数据来源

5. 我的备选页
   - 收藏列表
   - 冲稳保归类

## 7. 技术方案建议

对你现在这个阶段，最稳妥的技术路径是：

- 前端：微信原生小程序
- 数据处理：继续沿用 Python 脚本
- 数据服务：第一版可先用本地 JSON + 云开发数据库
- 部署：微信开发者工具 + 微信云开发

推荐目录结构：

```text
gaokao-miniapp/
  README.md
  miniprogram/
  cloudfunctions/
  data/
  scripts/
```

其中：

- `miniprogram/` 放小程序前端
- `cloudfunctions/` 放云函数
- `data/` 放整理后给前端/云函数使用的 JSON
- `scripts/` 放数据清洗和导出脚本

## 8. 最现实的开发顺序

不要一上来做界面，先按这个顺序推进：

1. 明确第一版输入和输出
2. 从现有数据里整理出推荐所需的统一 JSON
3. 先做一版可筛选的数据接口
4. 再做小程序页面
5. 最后补收藏、详情、风险提示

其中最关键的是第 2 步。

因为高考志愿小程序本质上不是“页面项目”，而是“数据决策项目”。如果底层数据结构不稳定，前端很快就会返工。

## 9. 第一版最小可行输入输出

建议先固定成下面这套：

输入：

- 北京考生
- 分数
- 位次
- 选科要求
- 是否有色弱等限制

输出：

- 推荐学校
- 推荐专业
- 冲稳保档位
- 风险状态
- 参考分数/位次
- 推荐理由

## 10. 下一步怎么开工

下一步最值得做的不是直接写页面，而是先做下面两件事：

1. 设计统一数据结构
2. 基于现有脚本导出小程序可用 JSON

只要这一步做好，后面的小程序页面开发会轻松很多。

如果继续推进，下一阶段我建议直接在这个目录下做两件具体工作：

- 创建小程序项目骨架
- 创建第一版推荐数据导出脚本
