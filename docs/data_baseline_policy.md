# 数据基线策略

## 1. 当前决策

当前项目的数据层，先以 `2025` 作为完整基线年。

这意味着：

- 学校名单以 `2025 年具有招生资格的普通高中学校名单` 为准
- 北京分数分布、位次映射、投档线等参考数据，优先使用 `2025` 年版本
- `2025` 年先做完整、做扎实，不追求同时混入 `2026` 的半成品数据

## 2. 为什么这样做

这样做的好处是：

- 当前模型、搜索、校排估算有稳定基准
- 不会因为 `2026` 年数据尚未完整发布而污染数据层
- 后续年度更新路径更清晰

## 3. 后续年度更新策略

当前约定：

- `2025`：作为首个完整可用基线年
- `2026`：等官方数据逐步发布后，再进入后台更新流程覆盖

更新方式：

- 不在前端临时拼接
- 通过后端数据更新流程统一替换
- 保留版本号和更新日志

## 4. 对当前开发的直接影响

接下来所有原型和数据结构，默认基于 `2025` 数据层建设：

- 北京公办高中标准库
- 学校搜索
- 校排入口
- 市排区间估算结构
- 志愿推荐输入层

## 5. 当前工作原则

一句话概括：

先把 `2025` 做全、做准、做稳，再做 `2026` 年更新。
