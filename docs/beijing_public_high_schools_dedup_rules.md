# 北京公办高中候选池去重规则

## 1. 当前目标

当前阶段不直接删除记录，而是先完成：

- 合并首批与第二批学校池
- 输出去重前总池
- 标记疑似重复、分校、校区和派生实体

## 2. 当前处理原则

### 保留原则

- 现阶段保留所有原始候选学校
- 不在没有复核前直接合并或删除
- 所有去重动作先基于规则标记，再进入人工确认

### 疑似重复识别规则

当前主要识别以下情况：

1. 同区内学校名称去掉括号说明、分校/校区等后缀后，基础名一致
2. 同区内一个学校名明显包含另一个学校基础名
3. 含“分校”“校区”“东校区”“西校区”“北校区”“南校区”“本校”等派生标记

## 3. 当前输出文件

- `beijing_public_high_schools.candidate_pool.pre_dedup.json`
  说明：合并后的去重前总池

- `beijing_public_high_schools.suspected_duplicates.json`
  说明：疑似重复/分校/校区清单

## 4. 下一步建议

1. 人工确认疑似重复清单
2. 决定哪些作为独立学校保留
3. 决定哪些降级为 aliases、校区说明或附属字段
4. 再生成正式标准库 seed

## 5. 主校、分校、校区的判定原则

当前阶段不建议把“主校”和“分校/校区”简单视为重复。

更稳的做法是把它们区分成“关系型实体”：

- 主校
- 分校
- 校区
- 品牌合作学校
- 待确认关系

### 为什么不能简单合并

因为很多“分校/校区/XX学校”是真实存在的招生实体，只是：

- 生源质量不同
- 办学历史不同
- 家长认知不同
- 录取预期不同

如果直接合并掉，会导致：

- 搜索结果失真
- 校排转市排映射失真
- 家长误以为“主校水平”可以直接套到分校

### 当前建议的判定优先级

#### 规则 1：是否为独立招生实体

如果一个学校在官方招生资格名单中以独立条目出现，应优先视为独立学校实体保留。

即使它名字里带：

- 分校
- 校区
- XX学校

也不要先删。

#### 规则 2：是否有独立办学辨识度

如果家长在现实咨询中会明确区分它和主校，例如：

- 北京中学
- 北京中学科技分校

则建议保留为独立实体，并建立与主校的关系字段。

#### 规则 3：是否只是同一学校的物理校区表达

如果后续核实发现只是同一学校内部的物理校区表达，而不是独立招生和独立认知单位，再考虑降级为校区说明。

### 当前推荐的数据处理方式

不要只做“去重”，而要做“关系建模”。

建议后续在标准库里增加这些字段：

- `entity_type`
- `parent_school_name`
- `relation_type`
- `independent_admission`
- `dedup_decision`

建议含义如下：

- `entity_type`
  - `main_school`
  - `branch_school`
  - `campus`
  - `co_branded_school`
  - `unknown`

- `relation_type`
  - `main_branch`
  - `main_campus`
  - `brand_cooperation`
  - `manual_review`

- `independent_admission`
  - `true`：按独立实体保留
  - `false`：更偏向主校附属表达

- `dedup_decision`
  - `keep_independent`
  - `merge_as_campus_note`
  - `merge_as_alias`
  - `manual_review`

## 6. 当前对这批学校的建议态度

对已经识别出的 24 组疑似关系，当前默认建议是：

- 先保留为独立实体
- 不直接并回主校
- 先给它们打关系标签
- 等后续补齐招生口径和学校属性后，再决定是否降级

换句话说：

“主校和分校的区别”在这个项目里，默认不是重复问题，而是关系问题。
