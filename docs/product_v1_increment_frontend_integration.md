# PRODUCT_V1 增量说明：小程序页面原型与真实接口衔接

## 1. 说明

这份文档用于补充 `PRODUCT_V1.md` 当前未完整体现的实现进展。

补充重点不是新需求，而是这几天已经稳定落地的事实：

- 校排入口页面原型已经存在
- 学校搜索原型已经存在
- 校排估算原型已经存在
- 当前前端页面与真实数据层之间的衔接顺序已经明确

## 2. 当前主链状态

当前校排入口主链已经形成四段：

1. 学校标准库
2. 学校搜索原型
3. 校排估算原型
4. 小程序页面原型

当前状态不是“还没做页面”，而是：

- 页面已经做出原型
- 数据层已经有真实底座
- 接口原型已经成型
- 页面尚未正式直连真实接口

## 3. 当前页面原型职责

当前小程序页面原型承担的是：

- 让家长先选中学校
- 约束校排入口最低必填项
- 在一页里完成“选学校 + 补输入 + 看估算结果”

它不是最终生产页，但已经能确认：

- 信息架构
- 视觉方向
- 交互路径

## 4. 当前页面原型已实现内容

当前已实现：

- 顶部产品主张
- 所在区选择
- 高中搜索输入
- 搜索候选下拉
- 选中学校确认块
- 校排名输入
- 年级总人数输入
- 排名口径切换
- 分数补充输入
- 原型级估算结果展示

## 5. 当前页面原型中哪些还不是正式接口

当前页面原型里，以下能力仍然属于前端示意逻辑：

- 学校搜索使用页面内置示例学校数据
- 估算结果使用页面内置演示估算逻辑

这并不是缺失，而是当前阶段的有意设计：

- 先确认页面交互是否顺畅
- 再接真实接口，避免一边调前端一边改数据层导致返工

## 6. 当前已存在的真实接口原型

当前已经可复用的真实能力包括：

- 学校搜索原型
- 搜索结果响应结构原型
- 校排转市排输入校验原型
- 校排转市排输出结构原型
- 完整联调原型（搜索 -> 选中学校 -> 校排估算）

## 7. 当前推荐的前后端接入顺序

建议按这个顺序完成真实接入：

1. 用真实学校标准库替换页面内置学校数据
2. 用真实搜索接口替换前端本地搜索逻辑
3. 用真实校排估算接口替换前端演示估算逻辑
4. 保持当前页面结构不变
5. 再接入定位页与推荐页

## 8. 当前阶段的成功标准补充

在前端与接口衔接这一层，当前应新增 3 个成功标准：

- 页面能够让家长在一页内完成校排入口的最低必要输入
- 页面能够正确区分主校、分校、校区、合作校
- 页面接入真实接口后，输出结果仍然保留：
  - 区间
  - 置信度
  - 说明文字
