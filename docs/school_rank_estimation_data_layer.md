# 校排转市排数据层说明

## 1. 目标

这一层不是前端页面，也不是最终算法实现，而是“校排转市排”能力所依赖的数据配置层。

它的作用是：

- 固定 2025 基线年的估算入口
- 区分官方参考层与学校估算层
- 为后续年度更新提供稳定结构

## 2. 数据层拆分

建议拆成三部分：

### 2.1 官方参考层

当前可直接复用：

- `beijing_rank_map.json`

用途：

- 分数 -> 北京市位次参考

### 2.2 学校标准层

当前可直接复用：

- `beijing_public_high_schools.standard_seed.v1.json`

用途：

- 学校标准化搜索
- 主校/分校/校区关系识别
- 后续学校层估算参数挂载

### 2.3 学校估算参数层

当前新增两类配置：

- `school_rank_estimation_tiers.v1.json`
- `school_rank_estimation_parameters.v1.template.json`

用途：

- 给每所学校或每类学校配置估算参数
- 作为后续每年更新时的可维护配置入口

## 3. 为什么单独做参数层

因为“校排转市排”不是只有一个公式。

至少会受到这些因素影响：

- 学校层级
- 主校 / 分校 / 校区
- 年级人数
- 排名口径
- 是否有分数
- 是否有历史校准样本

所以不能把所有逻辑写死在脚本里，必须把参数层拆出来。

## 4. 当前工作原则

当前阶段先不硬填大量学校参数，而是：

1. 先把配置结构固定
2. 先把基础档位定义出来
3. 后续按学校逐步补真实参数

## 5. 后续更新方式

后续当你和我一起做 2026 更新时，建议按这个顺序：

1. 更新 2026 官方数据
2. 更新学校标准库
3. 更新学校估算参数层
4. 重新跑模型和校验报告
