# Git 入门说明：给第一次开发小程序的自己看

## 1. Git 是什么

Git 可以理解为项目的“时光机”和“存档系统”。

你每完成一个阶段，就可以做一次存档。以后如果代码改坏了，可以回到之前的存档。

## 2. 这次我们为什么要用 Git

现在项目已经有：

- 产品手册。
- 学校标准库。
- 估算参数。
- 小程序页面。
- 数据脚本。
- 项目状态文档。

如果继续开发但没有 Git，后面会出现几个问题：

- 不知道某次改动具体改了哪些文件。
- 改错后不好恢复。
- 文档、数据、页面容易互相不同步。
- 后面如果接后端或者多人协作，会很乱。

所以现在做 Git 初始化是正确时机。

## 3. 常用概念

### 仓库 repository

就是被 Git 管理的项目文件夹。

本项目仓库是：

`D:\codex\school\gaokao-miniapp`

### 提交 commit

一次正式存档。

例如：

> 初始化北京高考小程序 V1 基线

以后你可以看到这次提交里包含了哪些文件。

### 分支 branch

可以理解为一条开发路线。

当前建议：

- `main`：稳定主线。
- `codex/baseline-v1`：当前由 Codex 帮你整理的 V1 基线分支。

### 暂存 stage

提交前的“打包区”。

Git 不是自动把所有文件都提交，而是先把要提交的文件放进暂存区，再提交。

## 4. 最常用的 5 个命令

以后你不一定要自己敲，但要知道它们是什么意思。

### 查看当前状态

```bash
git status
```

用途：

- 看哪些文件改了。
- 看哪些文件还没提交。

### 查看改了什么

```bash
git diff
```

用途：

- 看具体改动内容。

### 暂存文件

```bash
git add .
```

用途：

- 把当前目录下的改动放进待提交区。

### 提交存档

```bash
git commit -m "本次提交说明"
```

用途：

- 生成一个正式存档点。

### 查看提交历史

```bash
git log --oneline
```

用途：

- 看之前有哪些存档。

## 5. 我以后会怎么帮你用 Git

每次做比较大的功能前，我会先确认当前状态：

```bash
git status
```

每次做完一个阶段，我会建议：

1. 跑校验。
2. 更新文档。
3. 暂存改动。
4. 提交 commit。

这样项目会越来越稳，不会越做越乱。

## 6. 当前建议的提交节奏

建议以后按阶段提交：

- 完成一个页面，提交一次。
- 完成一个数据版本，提交一次。
- 完成一个脚本能力，提交一次。
- 完成一次产品手册更新，提交一次。

不要等十几天全部做完再提交，否则不好追踪。

## 7. 什么不要提交

以下内容不要进 Git：

- 密钥。
- `.env` 文件。
- 日志。
- 临时输出。
- 大量爬取原始数据。
- 微信本地私有配置。

这些已经在 `.gitignore` 里做了基础过滤。
